# 代码未公开 · 说明文案与面试话术

> 场景：RoboMaster 战队电控代码按队内管理要求不对外公开，但简历上贴了 `github.com/Moo-YY`。
> 目标：让面试官点进主页后，看到的是「工程化能力」，而不是「空仓库」。

---

## 0. 三条原则

1. **不伪造。** 不建空壳仓库、不贴与项目无关的搬运代码、不虚报私有仓库数量 —— 一问就穿，且直接触发诚信问题。
2. **把劣势换成维度。** 公开的不是源码，而是架构、流程、模块划分与可验证的量化数据。对嵌入式软件岗，这恰好是比「一堆 `.c` 文件」更稀缺的东西。
3. **声明放第一屏。** 别让人翻到页尾才发现没代码；主动说明比被发现更体面。

---

## 1. 主页 / README 版（书面）

已写入 `README.md` 顶部与「关于代码公开」一节：

> 本页所列项目源码因 RoboMaster 战队代码管理要求暂不公开；这里仅展示架构设计、模块划分与工程化实践。面试或技术交流时，可提供架构设计文档、目录结构、构建脚本与核心代码片段供讲解。

首屏简版：

> 本页所列项目源码因战队代码管理要求暂未公开，此处展示架构设计、模块划分与工程化实践。

## 2. 简历版（紧贴 GitHub 链接）

**推荐，一行写完：**

```
GitHub: github.com/Moo-YY（架构与工程化展示，源码因战队管理要求未公开）
```

**版面紧张时：**

```
GitHub: github.com/Moo-YY · 架构与工程化展示
```

要点：

- 括号里的说明不要比链接更显眼，字号可略小或同色。
- 链接必须是主页 `github.com/Moo-YY`，不要写成仓库地址 `…/Moo-YY/Moo-YY`。
- 检查**没有空格**（历史上出现过 `Moo- YY`）、没有大小写混写成 `Github:`。

## 3. 面试口头版（约 30 秒）

> "战队电控代码是队内共有的，按队里管理要求不对外公开，所以我 GitHub 上放的不是源码，而是架构设计和工程化实践：整车通信拓扑、五层软件架构、F4/H7 的复用方式、CI 门禁这些都能直接看到。如果您想核实实现细节，我可以现场提供架构文档、目录结构、构建脚本，也可以就核心片段做讲解。"

语气要点：**陈述事实 → 给出替代证据 → 主动开放核实**。不要解释太多、不要道歉。

## 4. 追问应答

**Q：代码不公开，我怎么判断你真做过？**
> 可以从三个层面对：一是架构可自洽，比如总线抽象 + 芯片适配层怎么让业务层零芯片头文件、为什么这样能在 F4/H7 之间零改动复用；二是过程可复现，比如用 SHA256 扫 144 组同名文件定收敛顺序，先迁哪批、怎么保证逐字节相同；三是细节可追问，比如 bxCAN 邮箱满时双路队列怎么避免竞态、中断补帧怎么保证时序。这些我可以现场展开。

**Q：具体能给点什么？**
> 架构设计文档、模块划分表、目录结构、CMake 构建脚本、CI 配置，以及脱敏后的核心片段截图。源码本身需要队里授权，我不会私下发。

**Q：是不是水平不够不敢开源？**
> 不是能力问题是归属问题 —— 这是战队多届共同维护的比赛代码，我个人的处置权有限。也正因如此我才把精力放在能公开的部分：把旧 Keil 工程重构成 CMake 多仓分层框架、把质量门禁做起来，这些设计思路本身不依赖源码就能讲清楚。

**Q：那 GitHub 链接的意义是什么？**
> 主要证明工程化习惯：分层怎么切、依赖怎么管、怎么用 CI 卡住回归。对嵌入式岗我觉得这比贴一段能跑的 demo 更有信息量。

## 5. 主页设置清单（接下来要做什么）

1. **同名仓库 `Moo-YY/Moo-YY` 保持 Public** —— 只有公开，README 才会渲染到 Profile 首页。它只放 `README.md` 与 `docs/`，不含源码，公开无泄密风险。
2. **Profile 侧栏**：补一句简介、学校 / 战队、所在地；链接填简历所载邮箱或本人主页即可。
3. **Pinned Repositories**：目前公开仓库只有 1 个，先把 `Moo-YY` 自己 pin 上，主页不至于空。这一步在网页端点「Customize your pins」完成，README 里控制不了。
4. **可选，增益最大的一步**：新建一个公开仓库放**可公开的通用物料**（CMake 模板、协议说明、工程化笔记、踩坑记录），主页便有第二个可点入口，贡献图也不会空。注意与战队代码彻底切分。
5. **简历链接复核**：`github.com/Moo-YY`，无空格、无多余路径。
6. **推送后验证**：无痕窗口打开 `github.com/Moo-YY`，确认 Mermaid 图渲染、徽章加载、两个空节已填充。

## 6. 不要这么写

| 反例 | 问题 |
| :--- | :--- |
| "代码涉密，无可奉告" | 生硬，像在回避 |
| "因赛事要求暂未开源，后续会开源" | 兑现不了就是给自己挖坑 |
| 贴大面积打码截图当证据 | 信息量低，反而显得心虚 |
| 在主页写 "另有 N 个私有仓库" | 无法验证，容易被当成夸大 |
| 把队友 / 队里传下来的开源方案写成自己实现 | 面试一追问就露馅，简历上已做过一次校正 |
